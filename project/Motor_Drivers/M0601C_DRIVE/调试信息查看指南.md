# M0601C 电机调试信息查看指南

## 调试器中可查看的变量

### 1. 主要调试结构体：`g_debug`

在Keil Watch窗口中添加 `g_debug`，展开查看所有字段：

| 字段名 | 类型 | 含义 | 正常值 |
|--------|------|------|--------|
| dmaRxStarted | uint8_t | DMA接收是否启动 | = 1 |
| rxCpltCallback | uint8_t | 接收完成回调触发次数 | > 0 且不断增加 |
| crcError | uint8_t | CRC校验错误计数 | = 0 |
| lastCrcCalc | uint8_t | 最后计算的CRC值 | 与lastCrcRecv相同 |
| lastCrcRecv | uint8_t | 最后接收的CRC值 | 与lastCrcCalc相同 |
| txStatus | uint8_t | 发送状态 | = 1 |
| rxBufRaw[10] | uint8_t[10] | 原始接收数据 | 有数据 |
| rxBufValid | uint8_t | 原始数据是否有效 | = 1 |

### 2. 电机反馈数据：`g_motorFeedback`

| 字段名 | 类型 | 含义 |
|--------|------|------|
| motorId | uint8_t | 电机ID |
| data[10] | uint8_t[10] | 完整的反馈帧数据 |
| isValid | uint8_t | 数据是否有效 |

### 3. 其他变量

- `g_feedbackCount` - 有效反馈帧计数
- `g_dmaRxStarted` - DMA启动状态（兼容旧代码）
- `g_rxCpltCallback` - 回调触发次数（兼容旧代码）
- `g_crcError` - CRC错误计数（兼容旧代码）
- `g_rxBufRaw[10]` - 原始数据（兼容旧代码）

## 如何在Keil调试器中查看

### 步骤1：编译下载
1. Keil中编译项目
2. 下载程序到开发板

### 步骤2：进入调试模式
1. Debug → Start/Stop Debug Session (Ctrl+F5)

### 步骤3：添加变量到Watch窗口
1. View → Watch Window → Watch 1
2. 在Watch窗口中输入：
   - `g_debug` （展开查看所有字段）
   - `g_motorFeedback` （展开查看数据）
   - `g_feedbackCount`

### 步骤4：运行程序
1. 点击 Run (F5)
2. 电机开始运行
3. 观察Watch窗口中的变量变化

## 反馈帧数据解析

### 原始数据格式（10字节）

| 字节 | 名称 | 说明 |
|------|------|------|
| DATA[0] | 电机ID | 1~4 |
| DATA[1] | 帧类型 | 反馈帧类型标识 |
| DATA[2] | 数据1 | 根据帧类型不同含义不同 |
| DATA[3] | 数据2 | |
| DATA[4] | 数据3 | |
| DATA[5] | 数据4 | |
| DATA[6] | 数据5 | |
| DATA[7] | 数据6 | |
| DATA[8] | 数据7 | |
| DATA[9] | CRC | CRC-8/MAXIM校验值 |

### 示例：如何手动解析

假设 `g_debug.rxBufRaw` = `{01, 74, 00, 1E, 00, 00, 00, 00, 00, 18}`

解析：
- DATA[0] = 0x01 → 电机ID = 1
- DATA[1] = 0x74 → 反馈帧类型
- DATA[2:3] = 0x001E = 30 → 可能是当前转速 30 RPM
- DATA[9] = 0x18 → CRC校验值

## 问题诊断

### 情况1：g_debug.dmaRxStarted = 0
**问题：** DMA启动失败
**解决：** 检查DMA配置

### 情况2：g_debug.rxCpltCallback = 0
**问题：** 从未触发接收中断
**原因：** 硬件连接问题
**解决：**
1. 检查 PB7 (RX) 是否连接到电机的TX
2. 确认电机已上电
3. 检查接线是否正确

### 情况3：g_debug.rxCpltCallback > 0 但 g_debug.rxBufRaw 全为0
**问题：** 收到数据但全为0
**原因：** 可能是时序问题
**解决：** 增加延时

### 情况4：g_debug.crcError > 0
**问题：** CRC校验失败
**原因：**
1. 数据传输干扰
2. 波特率不匹配
**解决：**
1. 检查波特率是否为115200
2. 检查线路干扰

### 情况5：g_debug.rxCpltCallback = 255
**说明：** 阻塞式接收测试成功
**结论：** 硬件连接正常，DMA配置可能有问题

## 调试技巧

### 技巧1：单步调试接收回调
1. 在 `HAL_UART_RxCpltCallback` 函数处设置断点
2. 运行程序，等待断点触发
3. 查看 `s_rxBuf` 数组内容
4. 单步执行，观察CRC计算过程

### 技巧2：实时监控
在Logic Analyzer中添加：
- `g_feedbackCount` - 查看计数曲线
- `g_debug.rxCpltCallback` - 查看接收频率

### 技巧3：对比发送和接收
1. 记录发送的指令帧
2. 对比接收的反馈帧
3. 验证数据格式是否正确

## 常见问题FAQ

**Q: 为什么g_debug.rxCpltCallback不断增加但g_motorFeedback.isValid = 0？**
A: 收到数据但CRC校验失败，检查lastCrcCalc和lastCrcRecv的值。

**Q: 为什么阻塞式测试成功但DMA不工作？**
A: DMA配置问题，检查DMA中断优先级和缓冲区地址。

**Q: 如何确认电机确实发送了数据？**
A: 使用示波器测量电机的TX引脚，发送指令后应该能看到数据波形。
